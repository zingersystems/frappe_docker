# Research

## Purpose

- Owns reference material, onboarding screenshots, requirements, and decision inputs for the Academia admissions implementation.

## Ownership

- `requirement/` contains written requirements and implementation guidance.
- `onboarding/` contains visual reference material such as screenshots.

## Local Contracts

- Treat requirement documents as source inputs; when implementation diverges, update or annotate durable docs only when the user requests documentation changes or the requirement itself changes.
- Do not overwrite reference images unless the user explicitly provides replacements or asks for image updates.
- Preserve names and context that link research material to implemented Frappe behavior.

## Work Guidance

- Prefer concise, dated notes for durable changes to requirements.
- Keep implementation details in app code and operational contracts in DOX files, not buried in research prose.
